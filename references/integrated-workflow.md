# 公司模板、PPT-Master与制作方法的协作

## 职责边界

本技能是公司PPT的综合入口，包含公司模板、语义选图和迭代规则。模板资产与原生结构由本仓库负责；内容设计和正文生成可以与单独安装的PPT-Master协作；最终可编辑性、品牌结构和原生渲染仍须验证。

PPT-Master开源上游：[hugohe3/ppt-master](https://github.com/hugohe3/ppt-master)。该项目以MIT许可证发布，版权与许可证见其 [LICENSE](https://github.com/hugohe3/ppt-master/blob/main/LICENSE)。本次整合是工作流与独立依赖协作，不是复制或内嵌上游全部代码；本机副本的版本和命令以实际安装内容为准，不假定它与上游最新版本完全相同。公司模板、第三方视觉素材的原有授权不因引用开源工具而改变。

## 按任务选择路线

| 任务 | 起点与做法 |
| --- | --- |
| 新建公司PPT | 先明确大纲与视觉关系，用公司原生结构页和内容版式构建成稿；需要时调用PPT-Master进行内容设计与正文制作 |
| 现稿小改或填充空页 | 直接修改最新PPTX及必要依赖，优先原生对象或范围明确的OOXML补丁，不运行会整稿重建的流程 |
| 调整章节或增删页面 | 最新PPTX仍是结构基线；重排内容后同步活动页顺序、目录、页码、备注与相关元数据 |
| 仅改动画、备注或播放顺序 | 保留正文与版式，使用PowerPoint原生能力并核对实际放映状态 |

## PPT-Master可用时

1. 从当前可用技能目录发现 `ppt-master`，读取该安装副本的 `SKILL.md` 及匹配的路线说明。不要硬编码某位用户的绝对安装路径，也不要照抄过期上游命令。
2. 已确认的公司模板、受众和风格继续有效；只有影响产出的新缺口才需要补充确认。用户已要求的局部修改可直接执行，不因引入协作工具而重启整套设计选择。
3. 使用其实际支持的内容处理、叙事设计、逐页设计、备注与验证能力。若采用SVG路线，按所安装版本的要求维护设计规范并逐页读取；正文应转换为原生对象，真实表格保留原生表格结构。
4. 若该版本明确要求某路线的前置条件，满足条件后再使用该路线；条件不具备时选择本技能可独立执行的原生制作方式，不伪称已运行完整PPT-Master流水线。
5. 中间产物只负责对应正文，不覆盖公司母版、占位符、主题、Logo、页脚、章节组合和现稿动画。合入时为新对象分配唯一ID、复制必要关系并验证。

本仓库不固定PPT-Master脚本参数或版本；若当前任务实际调用它，遵循该安装版本的生成和验证顺序，不跳过其明确的依赖检查。没有调用时也不宣称调用成功。

## 内容与视觉设计的复用方法

- 先写清这一页要让听众理解什么，再选择形式。概念用具体例子、关系图和组成示意，操作用截图、步骤与结果对照，发展脉络用时间轴或能力叠加图。
- 不把“演进”随意画成固定的高低等级，不把并列项目画成因果链；箭头、包围框、时间与数字必须表达真实关系。
- 一页主要讲一个观点，但不把它硬性变成一种版式。相邻页面按内容密度调整节奏，避免连续重复表格或等宽卡片。
- 产品功能比较先定义端别、版本、套餐和比较口径。基础课程可明确限定桌面常用入口，进阶接入放备注；用户素材与官方证据有矛盾时说明差异，不能把范围限制写成产品全局结论。
- 稳定的公司事实沿用已确认资料；易变的产品能力、价格和版本按需要核对官方来源并在备注记录时间。当前课程里的产品列表、免费额度、VPN或实验数字不写入本技能作永久知识。
- Logo用于真实涉及的厂商或产品，统一视觉大小并保留比例；不要用生成图伪造品牌。选择视觉资源仍按 `visual-selection.md`。

## 可移植性与交付

本技能不需要在每次调用时同时加载所有参考文件。新建、连续修改、截图教学各读对应参考即可。PPT-Master和Presentations工具不可用时，保留源文件并采用可用的原生制作与检查手段，准确说明未完成的检查；不为了工具适配降低为整页截图或重写公司模板。
